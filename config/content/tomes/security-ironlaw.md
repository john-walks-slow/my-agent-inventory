# 安全铁律

> 全局指令中的敏感信息防护规范。红线以内，没有例外。

## 总纲

任何工程项目中，**严禁**将真实敏感凭据硬编码或提交至版本控制。

## 其一：凭证隔离与环境变量注入

- 真实 API Key、Token、密码、私钥、Webhook 密钥，只能通过环境变量（`.env`，并加入 `.gitignore`）或外部凭据管理器注入。
- 源码与构建产物中一律不得出现真实密钥；含有效凭据的文件严禁进入 Git 追踪。

## 其二：文档与记录脱敏

- README、docs、排障记录、验证计划中的示例与回放，一律使用标准占位符：`<your-api-key>`、`demo-token`、`<your-domain.com>`、`127.0.0.1`。
- 公开文档禁止出现真实公网隧道域名、内网拓扑细节、个人手机号或可顺藤摸瓜的排查线索。

## 其三：测试脚本与 Mock 安全

- 单测、E2E、调测脚本严禁为"方便跑通"而塞真实 Key 或生产账号。
- Mock 与夹具使用显而易见的虚构占位符：RFC 5737 测试 IP、`mock-token`、`test-key`、公开 JWT 示例。

## 其四：例外范围澄清

本机的本地 Skills 与指令/环境文件（如 `~/.dsh/AGENTS.md`、`profiles/`）不在此限——它们是单机本地运维上下文，必须面向真实环境服务。**除此之外的一切项目工程、对外仓库与交付物，严格执行上述铁律。**
